# Bybit и OKX: фьючерсная демоторговля

**GO FOR VPS READ-ONLY VALIDATION.** Это разрешение проверить окружение и
готовность к подключению демосчетов; оно не разрешает отправку ордеров.

Модуль поддерживает последовательные фьючерсные ноги Bybit Demo и OKX Demo.
Полный цикл проверен offline с подменёнными ответами бирж. Работа с реальными
демосчетами и на VPS ещё не проверена; выполнение ордеров требует отдельного
разрешения владельца. Базовый PR #16 должен быть объединён раньше этого PR.

Bybit использует только `https://api-demo.bybit.com`, OKX — `https://www.okx.com`
с `x-simulated-trading: 1`. Используются только учётные данные из отдельного
демохранилища `age`; Testnet и production-маршруты в этом пути не поддерживаются.
Строка API-ключа сама по себе не доказывает, что ключ демонстрационный: владелец
должен сохранить ключи, созданные именно в демосредах. Баланс не подтверждает
право на размещение ордеров.

Режим и разрешение ордеров общие для процессов одного пользователя и его
`HOME`. Разрешение по умолчанию выключено, сбрасывается при смене режима и при
старте веб-сервера. `FARB_LIVE`, `DCA_LIVE`, `FARB_DRY_RUN` и Bybit Testnet
блокируют демоордера. Перед каждым запросом проверяется текущее общее состояние.
Остановка открытий оставляет возможность закрыть уже открытую пару.

Перед открытием проверяются доступность USDT-фьючерсов, размер и шаг ордера,
маржа, режим счёта, позиции и незавершённые заявки. Funding и комиссии не
являются обязательным условием ручного открытия. Автоматический сигнал стратегии
выбирает long на бирже с меньшим funding и short на другой, поэтому для самого
сигнала нужны свежие демоданные funding. Пользователь может задать направление
вручную без funding-сигнала. Ноги отправляются последовательно; вторая — только
после полного подтверждения первой и сверки позиций. Закрытие отправляется в
обратном порядке только с `reduceOnly`, подтверждением каждой ноги и проверкой
остатков на обеих биржах. При частичном исполнении или неизвестном результате
следующая нога и повторная отправка блокируются.

Для первоначальной проверки существующей установки владелец может выполнить через
Termius следующие команды без изменения сервера и обращения к биржам:

```sh
cd /opt/funding-arb-test
pwd -P
python3 --version
test -x .venv/bin/python && .venv/bin/python --version
command -v age
command -v age-keygen
git rev-parse --short HEAD
```

Вывод покажет окружение и текущий установленный коммит; пока код PR не установлен,
он не доказывает наличие изменений PR на VPS. Отсутствие `age` или `age-keygen`
нужно устранить до проверки защищённого хранилища.

Перед практической проверкой демосчетов на VPS владелец должен отдельно разрешить установку
изменений и проверить `age`, конфигурацию сервисного пользователя и демоключи.
Приведённые ниже команды выполняет владелец, после подготовки существующей
установки `/opt/funding-arb-test`, под тем же пользователем и с тем же `HOME`,
что использует сервер. Во время разработки они не выполнялись на VPS.

```sh
cd /opt/funding-arb-test
export FARB_DEMO_CREDENTIAL_STORE=age
.venv/bin/python scripts/cli/pure_futures_trade.py demo-mode
.venv/bin/python scripts/cli/pure_futures_trade.py demo-state
```

В существующей веб-панели сохраните отдельные демо-ключи Bybit и OKX и проверьте
подключения. Не вставляйте ключи в команды или журналы. После отдельного решения
владельца разрешение и ручное открытие пары выглядят так:

```sh
.venv/bin/python scripts/cli/pure_futures_trade.py demo-enable --confirm
.venv/bin/python scripts/cli/pure_futures_trade.py demo-open BTC --long-venue bybit --short-venue okx --trade-usd 50 --confirm
.venv/bin/python scripts/cli/pure_futures_trade.py demo-positions BTC
.venv/bin/python scripts/cli/pure_futures_trade.py demo-stop
.venv/bin/python scripts/cli/pure_futures_trade.py demo-close --confirm
```

`demo-stop` запрещает только новые открытия; `demo-disable` отключает и
закрывающие заявки. Указанные символ и объём — пример: владелец должен выбрать
размер, соответствующий правилам инструментов и балансу обоих демосчетов.
Для автоматического сигнала существующего pure-futures runner в его конфигурации
нужно явно задать `dry_run: false`, `pureFuturesArbitrage.demoBase` и
`tradeUsdPerPair`. После разрешения ордеров команда runner:

```sh
.venv/bin/python scripts/execution/run_pure_futures_spread.py --config /path/to/existing-config.json --once --json
```

Не запускайте одновременно автоматический и ручной сценарии для одной пары.
Межпроцессная блокировка и журнал не позволят открыть новую пару, пока состояние
предыдущей неопределённо. Подтверждённая закрытая пара перед новым открытием
повторно проверяется на отсутствие остатков и сохраняется в архив журнала.

При `reconciliation_required`, `close_reconciliation_required`, таймауте,
частичном исполнении или отказе остановите новые открытия и сохраните журнал.
Посмотрите заявки в демоинтерфейсах бирж и при необходимости используйте:

```sh
.venv/bin/python scripts/cli/pure_futures_trade.py demo-order BTC --venue bybit --client-id CLIENT_ID
.venv/bin/python scripts/cli/pure_futures_trade.py demo-cancel --venue bybit --client-id CLIENT_ID --confirm
.venv/bin/python scripts/cli/pure_futures_trade.py demo-positions BTC
.venv/bin/python scripts/cli/pure_futures_trade.py demo-resolve --confirm
```

Подставьте идентификатор именно неопределённого ордера из журнала. Отмена
записывается до запроса, не повторяется автоматически и сама по себе не доказывает
отсутствие исполнения. `demo-resolve` разрешает архивировать журнал только после
проверки конечного статуса возможных отправленных ордеров и отсутствия позиций
и заявок на обеих биржах. Если биржа не возвращает достоверный статус, журнал
остаётся заблокированным; не удаляйте его и не повторяйте ордер вслепую.
Журнал не содержит ключей, но может содержать торговые идентификаторы.

Локальная проверка состояния без обращения к биржам:

```sh
FARB_DRY_RUN=1 .venv/bin/python scripts/cli/demo_futures_readiness.py --journal
```

Она не подтверждает ключи, баланс или возможность исполнения. Проверки CLI и
сохранности ключей на существующем VPS описаны также в
[инструкции предварительной проверки](vps-pr16-preflight.md).
