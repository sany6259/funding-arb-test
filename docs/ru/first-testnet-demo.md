# Первый тест: Bybit testnet

**GO только для изолированной read-only проверки тестовых ключей после проверки и принятия изменений. Ордерный E2E — NO-GO до отдельного разрешения и проверки незакрытых рисков ниже.** Никаких реальных запросов на создание или отмену ордеров при разработке этого PR не выполнялось.

## Маршрут и предохранители

Выбранный сценарий — Bybit Testnet, BTC/USDT, прямой Cash & Carry: спот-покупка и шорт бессрочного фьючерса; закрытие в обратном порядке. Официальный REST Testnet — `https://api-testnet.bybit.com` ([документация Bybit](https://bybit-exchange.github.io/docs/v5/guide)); это отдельный контур от Demo Trading.

`BYBIT_REQUIRE_TESTNET=1` направляет выбранные Bybit API, котировки, funding и стакан в testnet, использует только `BYBIT_TESTNET_API_KEY` / `BYBIT_TESTNET_SECRET_KEY`, отклоняет другие биржевые адаптеры и HTTP-перенаправления авторизованных запросов. Неверное значение `BYBIT_REQUIRE_TESTNET` приводит к ошибке. Запись в testnet по умолчанию заблокирована; отдельное `BYBIT_TESTNET_ALLOW_ORDERS=1` намеренно включает запись и **не требуется для проверки ключей**. При тестовом режиме запуск веб-сервера запрещён: панель и её кошельки ещё не изолированы.

Эти ограничения действуют для реализованных путей выбранного сценария, а не как системный firewall. Запускайте только отдельный процесс без production-ключей, с сетевым разрешением исключительно testnet и в отдельном каталоге данных. Не запускайте общий сканер или веб-панель в этом процессе. CLI-раннеры сохраняют прежний приоритет `FARB_LIVE`/`DCA_LIVE`; не используйте эти переменные для testnet. Флаг `FARB_DRY_RUN` не является общей гарантией для произвольных API-запросов.

## Следующий шаг на VPS: только проверка подключения

1. После отдельного разрешения на подготовку VPS и проверки PR в Termius создайте **отдельный** каталог и окружение с этой версией кода; не меняйте работающий сервис. Разрешите исходящие запросы только к `api-testnet.bybit.com` с проверкой TLS. Создайте отдельный testnet-аккаунт и ключи через [Bybit Testnet](https://testnet.bybit.com/) по [официальной инструкции](https://bybit-exchange.github.io/docs/v5/guide), без разрешения вывода средств.
2. Безопасно передайте тестовые значения `BYBIT_TESTNET_API_KEY` и `BYBIT_TESTNET_SECRET_KEY` в окружение **только отдельного процесса**; не вставляйте значения в команды, чат, Git или журналы. В процессе не должно быть `BYBIT_API_KEY`, `BYBIT_SECRET_KEY`, `FARB_LIVE`, `DCA_LIVE` и `BYBIT_TESTNET_ALLOW_ORDERS`.
3. В отдельном каталоге запустите только read-only проверку:

   ```bash
   BYBIT_REQUIRE_TESTNET=1 FARB_DRY_RUN=1 .venv/bin/python scripts/cli/bybit_testnet_check.py
   ```

   Она делает только авторизованный `GET /v5/account/info`, не печатает ключи или ответ, не следует перенаправлениям и отказывает при отсутствии условий. `PASS` подтверждает только этот запрос; `NO-GO` означает остановку и проверку настройки без передачи секретов. Сам реальный запрос в рамках разработки PR **не выполнялся**.
4. Не открывайте сделку и не переключайте работающий сервис. Для первого ордерного цикла понадобится отдельное подтверждение владельца после проверки тестового баланса, минимальных размеров и условий изоляции.

## Исполнение и ограничения

Адаптер считает успехом только подтверждённый `Filled` с положительными исполненным количеством и ценой; для продажи и фьючерса количество должно соответствовать отправленному. `New`, частичное исполнение, потеря ответа и неизвестный результат передаются как `reconcile_required`. Исполнитель не открывает следующую ногу и не запускает автоматическую компенсацию при неопределённости; записывает данные для ручной сверки и блокирует новое открытие при таком состоянии. Фьючерсное закрытие использует `reduceOnly`.

**Ограничение:** состояние неопределённости сохраняется после получения результата, но пока нет долговечного журнала намерения до отправки и блокировки параллельных процессов. Поэтому авария процесса в момент запроса или одновременные запуски требуют ручной сверки testnet и не позволяют утверждать безопасность реального двухногого E2E. Автоматическая компенсация допустима только для явно отклонённой ноги; её результат также необходимо проверить. Остановка процесса сама по себе не закрывает позиции.

Offline-регрессия: `.venv/bin/python -m pytest scripts/tests/test_first_demo_smoke.py -q`. Все сетевые вызовы и ключи в тестах подменены. Успех тестов не подтверждает доступность testnet, фактические комиссии, ликвидность или исполнение реального ордера.
