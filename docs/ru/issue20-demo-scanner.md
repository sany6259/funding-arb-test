# Демо-сканер и запуск backend (Issue #20)

> Примечание: последующий PR #23 меняет демосканер и CLI; актуальный порядок и ограничения описаны в [инструкции Issue #22](issue22-demo-controls.md). Ниже сохранено описание состояния PR #21.

Изменения подготовлены поверх PR #18 и его зависимости PR #16. VPS в этой
работе не изменялся. Слияние, установка и перезапуск сервиса выполняются только
после проверки владельцем.

В режиме `demo` сканер использует только анонимные GET рыночных данных Bybit
`api-demo.bybit.com` и OKX `www.okx.com` с `x-simulated-trading: 1`. Результаты
комиссий используют сохранённые VIP-тарифы, а не приватные API счетов. Другие
биржи из выбранного списка в демосканировании не запрашиваются; доступность
рыночных данных реальных демосред необходимо отдельно проверить на VPS. Это
сканирование не включает разрешение на ордера. Торговые запросы и прежние
приватные production-маршруты остаются под своими серверными защитами.
`FARB_DRY_RUN=1` блокирует сетевые запросы сканера, демо-проверки и отправку
уведомлений; чтобы
сканировать, этот флаг должен быть выключен, при этом разрешение демоордеров
по умолчанию остаётся выключенным. По той же причине сетевой Testnet-check с
обязательным для него `FARB_DRY_RUN=1` также остаётся заблокированным.

`start.sh` теперь запускает `scripts/launch_backend.py`: он загружает `.env`
из корня проекта как данные, без исполнения shell-команд и без печати значений.
Уже заданные переменные процесса/systemd имеют приоритет. Отдельная команда
для существующей systemd-конфигурации, которую владелец может использовать при
согласованном обновлении `ExecStart`:

```ini
WorkingDirectory=/opt/funding-arb-test
ExecStart=/opt/funding-arb-test/.venv/bin/python /opt/funding-arb-test/scripts/launch_backend.py --host 127.0.0.1 --port 8787
```

Укажите в существующем unit подходящего пользователя и убедитесь, что он может
читать существующий `/opt/funding-arb-test/.env` и identity `age`; не создавайте
и не заменяйте identity без отдельного решения владельца. Храните `.env` и
identity с ограниченными правами. Не выводите содержимое `.env`, переменные
`Environment`, ключи или identity в терминал, issue или журналы. Само наличие
`.env` не доказывает, что учётные данные демонстрационные.

После отдельного разрешения на обновление VPS установите проверенный коммит в
существующую установку с сохранением локальных настроек, выполните установку
зависимостей и сборку интерфейса, затем обновите `ExecStart` при необходимости
и перезапустите сервис. До этого проверьте текущий статус Git и сохраните
локальные изменения; не выполняйте `git reset --hard` и не копируйте `.env`.
После перезапуска проверьте `/positions`, `/cex`, `/backtest`, статус режима и
сканер. Не включайте разрешение ордеров и не отправляйте их. CLI `demo-positions`
из PR #18 по-прежнему требует разрешения демоордеров; этот PR его не меняет.
