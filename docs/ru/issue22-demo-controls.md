# Демоторговля Bybit и OKX (Issue #22)

Изменения находятся в Draft PR #23 поверх #21 → #18 → #16. Код и тесты проверялись только offline. VPS, доступность API, настройки демосчетов и реальные ответы бирж **не проверены**. Статус: подготовлено к отдельной read-only проверке на VPS; отправка первого демоордера требует отдельного разрешения владельца.

## Управление

Выберите **Демо** и сохраните отдельные демоключи Bybit и OKX через существующую страницу CEX. Торговый backend использует age-хранилище (`FARB_DEMO_CREDENTIAL_STORE=age`) и действующую identity `FARB_DEMO_AGE_IDENTITY`; не создавайте и не заменяйте identity без решения владельца. Баланс не подтверждает готовность к исполнению.

На странице **Позиции** доступны единое разрешение демоордеров на текущий запуск backend, остановка открытий, открытие/закрытие пары, отдельные Long/Short, просмотр позиций, заявок, комиссий, funding, PnL и журнала. Доступ к этим действиям ограничен localhost: для VPS используйте SSH-туннель, не публикуйте backend напрямую. Открытие из сигнала сканера использует тот же демоисполнитель. Разрешение ордеров и автозапуск сбрасываются при перезапуске или смене режима.

Автостратегия использует только фьючерсы Bybit/OKX, сканирует рынок, повторно проверяет актуальные комиссии демосчетов, глубину, funding, инструменты, доступную маржу и указанные пределы перед последовательным открытием. Для открытой пары она сверяет позиции и закрывает их по заданному funding-порогу. Настройки сохраняются; для следующего запуска после перезапуска требуется новое разрешение владельца. При недоступности рыночных данных ожидание и повторное чтение не создают ордеров. При неоднозначном ордере стратегия останавливается.

Сканер проверяет фактические комиссии и стакан для первых десяти кандидатов; остальные и кандидаты с недоступными данными помечаются как непроверенные и не показываются как подтверждённые сигналы. Чистая доходность остаётся оценкой, рассчитанной по текущему стакану и комиссиям для заданного размера. При открытой позиции или расхождении сделка блокируется preflight. Демо-сканирование spot и Bitget не используется. Для внешней открытой заявки сейчас требуется непустой буквенно-цифровой `clientOrderId` длиной до 24 символов; другие идентификаторы требуют управления через биржу. История ограничена доступностью и сроком хранения данных биржи; пагинация ограничена 20 страницами и при превышении сообщает об ошибке, а не выдаёт неполную историю за полную.

`FARB_DRY_RUN=1` запрещает сетевые запросы и ордера; для настоящих демоданных его нельзя включать. Флаг `FARB_LIVE` не разрешает демоордера и блокирует демоисполнитель. Значения в systemd имеют приоритет над `.env`; не печатайте ни их, ни `.env`. Backend и демо-CLI загружают корневой `.env` как данные, без выполнения shell-кода.

## Сверка при сбое

При timeout, отказе или частичном исполнении не повторяйте отправку. В панели откройте журнал и состояние позиций/заявок. При необходимости отмените записанную неопределённую заявку или открытую демозаявку с известным `clientOrderId` и нажмите **Сверить журнал**. Отмена отправляется один раз; её отдельное намерение блокирует другие ордера до подтверждения терминального статуса и согласованности позиций. Сверка использует идентификаторы и терминальные статусы, проверяет остатки и не отправляет ордер. При подтверждённом частичном исполнении остаток можно закрыть отдельной командой `reduceOnly`; для восстановленной пары кнопка закрытия последовательно закрывает проверенные остатки обеих бирж. Если данные отсутствуют или противоречивы, журнал продолжает блокировать новые сделки; проверьте обе площадки вручную. Состояние `closed_confirmed` означает подтверждённые нулевые позиции, а не просто принятие заявки.

## Подготовка существующего VPS

Все команды ниже выполняет владелец; они не выполнялись в рамках PR. До отдельного разрешения не меняйте работающий сервис, identity, `.env` или ключи. Для просмотра окружения через Termius:

```bash
cd /opt/funding-arb-test
git status --short --branch
git rev-parse HEAD
python3 --version
node --version
command -v age
command -v age-keygen
systemctl list-units --type=service --all | grep -i funding
ps -eo pid,comm | grep -E 'python|uvicorn|node'
```

Не показывайте вывод с секретами, командные строки процессов, переменные окружения или содержимое unit-файла. Сопоставьте текущий сервис и пользователя с расположением имеющейся identity без её чтения. При локальных изменениях остановитесь и сохраните их до любых обновлений.

После отдельного разрешения на обновление и проверки полного diff остановите стратегию, убедитесь, что нет отправляемого ордера, и согласованно остановите фактически найденный systemd unit. Сохраните журналы и данные открытых позиций. Затем владелец может получить ветку без merge, указав **проверенный SHA** из PR (следующие команды меняют существующую установку):

```bash
cd /opt/funding-arb-test
test -z "$(git status --porcelain --untracked-files=normal)" || { echo 'Есть локальные изменения — остановитесь'; exit 1; }
git fetch origin feat/issue-22-demo-controls
read -r -p 'Проверенный полный SHA PR: ' reviewed_sha
git merge-base --is-ancestor "$reviewed_sha" origin/feat/issue-22-demo-controls || { echo 'SHA не принадлежит проверенной ветке'; exit 1; }
git switch --detach "$reviewed_sha"
.venv/bin/python -m pip install -r server/requirements.txt
npm ci --prefix web
npm run build --prefix web
```

Не использовать `git reset --hard`. Изменение `ExecStart` или перезапуск фактически найденного systemd unit выполняются только после проверки владельцем; пример запуска backend приведён в [инструкции Issue #20](issue20-demo-scanner.md). Убедитесь, что сервис слушает только `127.0.0.1:8787`, а разрешение ордеров после запуска выключено.

Для offline-тестов с фиктивным HOME и запретом внешних сокетов:

```bash
cd /opt/funding-arb-test
test_home=$(mktemp -d)
env -i HOME="$test_home" USERPROFILE="$test_home" PATH="/usr/bin:/bin" \
  PYTHONPATH="$PWD/scripts/tests/offline_guard" \
  HTTP_PROXY=http://127.0.0.1:9 HTTPS_PROXY=http://127.0.0.1:9 \
  NO_PROXY=127.0.0.1,localhost .venv/bin/python -m pytest scripts/tests -q
```

## Приёмка демосреды

1. Подключите SSH-туннель к localhost backend и откройте панель. Не включайте разрешение ордеров. Убедитесь, что выбран demo и в журнале нет неопределённой операции.
2. Проверьте Bybit Demo и OKX Demo: состояние ключей, доступный баланс, позиции и заявки, историю и ошибки. Не отправляйте секреты в чат. Проверка баланса не доказывает, что ордера работают.
3. Запустите сканер, проверьте время обновления, комиссии, стакан, источники данных и сообщения об ошибках. Данные без подтверждённых расходов не являются подтверждённым сигналом.
4. CLI для read-only проверки из каталога проекта:

   ```bash
   .venv/bin/python scripts/cli/pure_futures_trade.py demo-state
   .venv/bin/python scripts/cli/pure_futures_trade.py demo-positions BTC
   ```

5. Только после отдельного разрешения на демоордера: включите разрешение в панели, проверьте размеры и направления, откройте тестовую пару вручную, проверьте обе позиции и заявки, затем закройте пару и подтвердите нулевые остатки. Для автоматической проверки задайте лимиты и пороги, запустите стратегию, наблюдайте открытие и закрытие, затем остановите её. При любом неизвестном состоянии остановитесь и выполните сверку по инструкции выше.

CLI автоматической стратегии использует те же mode, журнал и межпроцессную блокировку. Пример параметров без секретов: `templates/config.demo.futures.example.json`; запуск `scripts/execution/run_pure_futures_spread.py --config ... --once` может отправить демоордера при действующем разрешении и поэтому требует отдельного решения владельца.
