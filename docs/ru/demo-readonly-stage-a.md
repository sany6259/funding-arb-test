# Демо-подключение: этап A

Этап A позволяет сохранить отдельные демоключи Bybit, OKX и Bitget и выполнить
только авторизованную проверку баланса. Открытие, закрытие и другие записи через
адаптеры этой версии отключены во всех режимах, включая CLI и автоматические
процессы с тем же кодом. Проверка баланса **не подтверждает готовность к
исполнению ордеров**. Реальная торговля в панели недоступна.

| Биржа | Официальная демосреда и read-only запрос | Изоляция | Баланс и ограничения |
| --- | --- | --- | --- |
| Bybit | [Demo Trading](https://bybit-exchange.github.io/docs/v5/demo), `https://api-demo.bybit.com`, `GET /v5/account/wallet-balance` | Отдельный ключ Demo Trading, подпись HMAC SHA-256, `X-BAPI-*`. Testnet `api-testnet.bybit.com` — другая среда; защита PR #14 сохранена. | Доступный баланс Unified Account указывается биржей в USD для всего счёта, не как USDT одного актива. Spot и linear/inverse API описаны биржей, но конкретный инструмент не проверен. |
| OKX | [Demo Trading Services](https://www.okx.com/docs-v5/en/#overview-demo-trading-services), `https://www.okx.com`, `GET /api/v5/account/balance` | Отдельный demo key и passphrase, HMAC SHA-256/base64, обязательный заголовок `x-simulated-trading: 1`. Имя хоста общее с production. | Доступный USDT в Trading Account (`availBal`); отсутствие значения отображается как неизвестное. Биржа описывает spot и swap; наличие конкретных инструментов и региональных доменов не проверено. |
| Bitget | [Demo REST API](https://www.bitget.com/api-doc/classic/demotrading/restapi), `https://api.bitget.com`, `GET /api/v2/spot/account/assets` | Отдельный demo key и passphrase, HMAC SHA-256/base64, обязательный заголовок `paptrading: 1`. Имя хоста общее с production, для демо требуется верификация. | Доступный USDT в Spot Account; фьючерсный баланс не проверяется. Биржа описывает demo spot и futures; конкретные perpetual-контракты не проверены. |

Демоадаптер не использует production-ключи из окружения и не следует
переадресациям. При сохранении он отклоняет ключ, совпадающий с уже известным
этому процессу production- или Bybit Testnet-ключом. **По самой строке ключа
нельзя надёжно определить среду:** принадлежность неизвестного ключа проверяет
биржа при последующем запросе. Используйте только ключи, созданные в демосреде;
для OKX и Bitget теоретически можно ошибочно передать неизвестный production
ключ на общий хост с демозаголовком. До практической проверки это ограничение
нельзя считать устранённым. В деморежиме проверенные legacy-сетевые пути и сканер отключены; уже запущенные старые версии и внешние программы этой защитой не управляются.

## Ключи и режим

Кнопки панели сохраняют, обновляют и удаляют ключ отдельно для каждой биржи.
Доступны системный keyring (по умолчанию) и явно выбранный backend `age`
(`FARB_DEMO_CREDENTIAL_STORE=age`). Последний подходит для headless-сервиса без
D-Bus: API-ключи передаются в `age` через стандартный ввод и хранятся только в
зашифрованных файлах `~/.funding-arb/demo-credentials/demo-<биржа>.age`. Отдельная
личная идентичность по умолчанию находится в `~/.funding-arb/demo-age.key`,
должна принадлежать пользователю сервиса и иметь права не шире `0600`.
Можно указать иной путь через `FARB_DEMO_AGE_IDENTITY`.

**Граница защиты:** шифрование защищает от случайного раскрытия шифротекста,
но процесс того же пользователя, способный прочитать личную идентичность и
шифротекст, может расшифровать данные. Резервируйте ключ отдельно и не
публикуйте его; потеря ключа делает записи нечитаемыми. Реальные демоключи не
записываются в конфигурацию, логи или обратно в браузер. Переключение backend
не переносит ключи автоматически и не использует plaintext fallback.

Системный keyring требует доступной и разблокированной Secret Service/D-Bus
сессии и не гарантированно работает в headless systemd. Для `age` требуются
программы `age` и `age-keygen` в PATH пользователя сервиса. Права на каталог
хранилища и идентичности проверяются; при ошибке сохранение и чтение запрещены.
Значения формы очищаются после операции. Отдельное хранение live-ключей и
включение live-торговли пока не реализованы.

[Пошаговая диагностика VPS до развёртывания](vps-pr16-preflight.md) использует
только фиктивные данные и не изменяет работающий сервис. Конкретный VPS и его
systemd-конфигурация ещё не проверялись. Не вставляйте реальные ключи в чат,
shell, CI или GitHub.

Выбранная симуляция или демо сохраняется в `~/.funding-arb/execution-mode.json`.
Сервер, CLI и фоновые процессы данной версии читают этот общий файл под одним
пользователем и `HOME`, с межпроцессной блокировкой; повреждённое состояние
отклоняется. При переходе в демо уже начатые запросы через общий шлюз должны
завершиться, новые отклоняются. Файл не содержит секретов или разрешения на
ордера. Разные учётные записи/HOME, старые версии кода и внешние программы не
синхронизируются. Отдельные асинхронные SDK других бирж проверяют режим перед
запросом, но не удерживают общую блокировку на всём сетевом вызове; их процессы
во время проверки демо необходимо остановить. Даже при сохранённом режиме
ордера адаптеров заблокированы, в том числе Bybit Testnet.

## Аварийные позиции и дальнейшая проверка

Эта версия блокирует и автоматическое закрытие ранее открытых реальных позиций,
включая существующие CLI/watcher. До любого обновления нужно сверить активные
позиции и остановить старые торговые процессы. При аварии останавливайте
автоматизацию и управляйте реальными позициями непосредственно в интерфейсах
бирж по собственному регламенту; откат сам по себе не закрывает позиции и не
отменяет заявки. Отдельного безопасного аварийного режима внутри бота нет.

До отдельного решения о развёртывании никакие команды на VPS не выполнялись.
Для будущей проверки подготовьте изолированный экземпляр без production-ключей
и без параллельных торговых процессов; установите защищённый keyring, соберите
интерфейс и запустите сервер от одного пользователя на `127.0.0.1:8787`.
Подключайтесь по SSH-туннелю, не публикуйте панель в интернет. Локальная
проверка ключей отвергает forwarded-заголовки, поэтому reverse proxy может не
подойти. После отдельного разрешения на read-only запросы выберите «Демо»,
сохраните демоключи, проверьте каждую биржу и сравните доступный баланс с её
демосчётом; после перезапуска сервера проверьте наличие маски и выбранный режим.
Сканер в деморежиме отключён; перед переключением дождитесь завершения предыдущих запросов.

В PR выполнены только тесты с моками, без реальных API и ордеров. До первого
демоордера необходимы отдельный этап B, журнал намерений до отправки,
межпроцессная блокировка, preflight, подтверждение исполнения и reconciliation,
безопасное закрытие, проверка инструментов и отдельное разрешение владельца.
