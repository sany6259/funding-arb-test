# Демо-подключение: этап A

Этап A проверяет авторизацию и баланс, но не отправляет ордера. По умолчанию
выбрана симуляция; переход в демо сам по себе ничего не исполняет. Реальная
торговля и демо-ордера в панели недоступны. Не использовать эту версию для
управления открытыми реальными позициями: открытие и закрытие через backend
заблокированы, включая закрытие позиций, созданных ранее. Подпись ордеров
браузерным кошельком и старые формы изменения торговых ключей тоже отключены.

Здесь читается только доступный USDT spot-аккаунта, баланс фьючерсов не проверяется. |

Эта реализация имеет только перечисленные GET-маршруты и не подтверждает
готовность любой пары для торговли. Нет fallback на другой хост, переадресации
запрещены. Публичные рыночные данные сканера могут поступать из production API;
это не демонстрация исполнения. Существующий CLI Bybit Testnet остаётся
отдельным сценарием и не используется панелью для Demo Trading.

Для каждой проверки введите **демоключ конкретной биржи** с правом чтения,
без права вывода. Данные разных бирж вводятся в отдельные формы и не записываются
в настройки, окружение процесса или файл; после проверки форма очищается.
Сервер использует только переданные поля, не берёт production-ключи из окружения,
а ответ содержит маску и USDT-баланс. Отсутствие USDT в ответе не выдается за
нулевой баланс. Персистентного хранилища отдельных ключей для разных сред пока
нет; ключ надо вводить заново после каждой проверки. Ответ об ошибке намеренно
не содержит текст ошибки биржи или ключи. Не вставляйте ключи в GitHub, чат,
команды shell, логи или CI.

## Проверка после ревью и отдельного решения о развёртывании

Никакие команды ниже не выполнены на VPS в рамках этой задачи. До установки
сверьте открытые позиции на биржах: панель этой версии не сможет их закрыть.
При аварии остановите автоматизацию и управляйте реальными позициями напрямую
через интерфейсы бирж по собственному регламенту. Для возврата используйте
предыдущую проверенную версию, предварительно сверив состояние позиций и ключей;
сам откат не закрывает позиции и не отменяет заявки.

В тестовом экземпляре без production-ключей и без параллельных торговых
процессов соберите интерфейс (`cd web && npm ci && npm run build`), затем из
корня репозитория запустите `FARB_DRY_RUN=1 python -m server.main --no-reload`.
Используйте один процесс сервера: выбранный режим хранится только в памяти и
сбрасывается в симуляцию при перезапуске. Сервер должен слушать только
`127.0.0.1:8787`; для доступа с рабочего компьютера используйте SSH-туннель
к этому адресу и откройте `http://127.0.0.1:8787`. Не публикуйте панель в
интернет. Проверка ключей отклоняет нелокальных клиентов и запросы с
forwarded-заголовками; обычный reverse proxy может поэтому не подойти.

После отдельного разрешения владельца на read-only запрос выберите «Демо»,
поочерёдно проверьте каждую биржу и сравните показанный баланс с её демосчётом.
Обычный запуск сервера может делать публичные запросы сканера; кнопка проверки
отправляет авторизованный GET бирже. До такого разрешения используйте только
локальные тесты с моками: `FARB_DRY_RUN=1 .venv/bin/python -m pytest scripts/tests/ -q`
и `cd web && npm run build && npm run test:i18n`.

Проверка в этом PR выполнена только с моками. Приём реальных API-ответов,
права конкретных ключей и доступность инструментов остаются неподтверждёнными.
Демо E2E с журналом намерений, межпроцессной блокировкой, сверкой исполнения и
позиций, preflight и безопасным закрытием относится к этапу B в отдельном PR.
До его реализации и отдельного разрешения торговля в этой панели недоступна.
Другие CLI, процессы и средства прямого доступа к биржам этим ограничением не
охвачены.
